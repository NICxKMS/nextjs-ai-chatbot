# C3 Security Fix Spec — Header Spoofing & Defense-in-Depth

> Generated by Thoth research. All code changes are exact — apply verbatim.

---

## Context

Durga validation of Cycle 3 found that internal proxy headers (`x-session-type`, `x-guest-user-id`) are never stripped from incoming client requests, enabling header spoofing. The `x-session-type` fast-path in `getAppSession()` (C3-A) widened this from a fallback path to a direct auth bypass on non-proxied API routes.

---

## Fix 1 (P0-a): Strip internal headers at proxy entry

**File:** `proxy.ts`
**Location:** After line `const requestHeaders = new Headers(request.headers)` (~line 176)

**Insert immediately after the `new Headers` line:**
```typescript
// ── Strip internal headers that must only be set by the proxy ──
// These headers control session resolution in getAppSession(). If not
// stripped, a client can spoof them on routes that match the proxy, or
// exploit the catch-block fallthrough. Defense-in-depth: session.ts
// also validates independently, but the proxy is the first line.
requestHeaders.delete("x-session-type")
requestHeaders.delete("x-guest-user-id")
```

**Why:** Client-sent `x-session-type` and `x-guest-user-id` must never propagate to downstream route handlers. Stripping at entry ensures all proxy code paths start from clean state.

## Fix 3 (P1-a): Remove `x-guest-user-id` header trust in `resolveGuestSession()`

**File:** `lib/auth/session.ts`
**Location:** `resolveGuestSession()` function (~lines 96-114)

**Change from:**
```typescript
async function resolveGuestSession(): Promise<AppSession | null> {
	try {
		// Fast path: proxy already verified the guest token
		const headerStore = await headers()
		const proxyVerifiedUserId = headerStore.get("x-guest-user-id")

		if (proxyVerifiedUserId) {
			return { user: { id: proxyVerifiedUserId, type: "guest" } }
		}

		// Fallback: verify the JWT ourselves (e.g. direct server action calls)
		const cookieStore = await cookies()
		const guestToken = cookieStore.get(GUEST_COOKIE_NAME)?.value

		if (!guestToken) return null

		const result = await verifyGuestToken(guestToken)
		if (!result) return null

		return { user: { id: result.userId, type: "guest" } }
	} catch {
		return null
	}
}
```

**Change to:**
```typescript
/**
 * Resolve guest session from the guest_token cookie.
 *
 * Always verifies the guest JWT from the cookie — never trusts proxy headers
 * for the actual userId. The proxy's `x-session-type: "guest"` hint is consumed
 * by `getAppSession()` to skip the Supabase round-trip (the major perf win),
 * but the guest identity is always verified here via JWT signature check.
 *
 * Cost: ~0.5ms HMAC-SHA256 verification per guest request.
 * Benefit: complete defense-in-depth — even if proxy headers are spoofed or
 * a route bypasses the proxy, the session identity is cryptographically verified.
 */
async function resolveGuestSession(): Promise<AppSession | null> {
	try {
		const cookieStore = await cookies()
		const guestToken = cookieStore.get(GUEST_COOKIE_NAME)?.value

		if (!guestToken) return null

		const result = await verifyGuestToken(guestToken)
		if (!result) return null

		return { user: { id: result.userId, type: "guest" } }
	} catch {
		return null
	}
}
```

**Why:** The `x-guest-user-id` header was a Layer 2 optimization saving ~0.5ms by skipping JWT verification. This is negligible compared to the Layer 1 optimization (`x-session-type` skipping Supabase's ~100-200ms `getUser()` call). Removing the header trust eliminates the entire spoofing attack surface while keeping 99.7% of the performance benefit.

**Impact on `headers()` import:** After this change, `resolveGuestSession()` no longer calls `headers()`. However, `getAppSession()` still imports and uses `headers()` for `x-session-type`, so the import stays.

## Fix 4 (P1-b): Clean up proxy catch block

**File:** `proxy.ts`
**Location:** The catch block in the guest-eligible section (~lines 248-251)

**Change from:**
```typescript
		} catch (error) {
			// Guest token operations can fail if GUEST_JWT_SECRET is missing.
			// Continue without guest token — degraded experience is better than crash.
			logger.error("[proxy] Guest token lifecycle error", { error: String(error) })
		}
```

**Change to:**
```typescript
		} catch (error) {
			// Guest token operations can fail if GUEST_JWT_SECRET is missing.
			// Continue without guest token — degraded experience is better than crash.
			// Ensure internal headers are clean so downstream doesn't see stale/partial state.
			requestHeaders.set("x-session-type", "none")
			requestHeaders.delete("x-guest-user-id")
			logger.error("[proxy] Guest token lifecycle error", { error: String(error) })
		}
```

**Why:** If `verifyGuestToken` or `rotateGuestToken` throws mid-flow, `x-session-type` and `x-guest-user-id` may have been partially set. Explicitly resetting to clean state in the catch block ensures downstream `getAppSession()` treats this as "no session" rather than a partial/inconsistent state.

## Architecture Notes

- **`x-session-type` hint is preserved.** `getAppSession()` still reads it to skip Supabase for guest/anonymous visitors. This is the big performance win (~100-200ms saved).
- **`x-guest-user-id` is now write-only from the proxy's perspective.** The proxy still sets it (useful for logging, rate limiting in the proxy itself), but `session.ts` no longer reads it.
- **No new dependencies or abstractions introduced.** All fixes are subtractive (removing trust) or additive (adding strips/resets).
