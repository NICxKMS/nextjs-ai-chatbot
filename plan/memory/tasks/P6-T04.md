## Deviations

**Original design:** Copy `oldapp/components/elements/model-selector.tsx` verbatim as AI element. The old element wraps Dialog + Command (cmdk) primitives for a searchable command palette UI.

**What was done:** Created an adapted AI element using Popover from radix-ui (`radix-ui` unified package v1.4.3, already installed) instead of Dialog + Command.

**Why:** Dialog and Command UI primitives do not exist in the new project (`components/ui/` has no `dialog.tsx` or `command.tsx`), and `cmdk` is not in `package.json`. Creating both missing primitives for a single component would be scope creep (Dialog/Command belong to P0-T11 or a separate task). Popover provides equivalent floating-panel-with-focus-trap behavior with zero new dependencies.

**Trade-offs:** The Popover-based approach loses cmdk's built-in fuzzy matching and keyboard navigation (arrow keys to move between items). Custom search filtering is implemented instead (name, description, provider, providerModelId substring matching). Keyboard navigation works via Tab/Shift+Tab to move between items, which is standard but less polished than cmdk's arrow-key model. If cmdk support is added later, the AI element can be swapped without changing the feature wrapper.

**Root component renamed:** The AI element exports `ModelSelectorRoot` (not `ModelSelector`) to avoid naming collision with the feature component's `ModelSelector` export. Feature consumers import from `features/models/components/model-selector.tsx`.

## Findings

1. **Cookie name consistency:** The `MODEL_COOKIE_NAME = "chat-model"` constant matches the one used in `features/models/lib/models.ts` → `getDefaultModel()`, ensuring server-side reads are aligned with client-side writes.

2. **`document.cookie` lint warning:** Biome warns about direct `document.cookie` assignment (suggests Cookie Store API). This matches the existing pattern in `components/ui/sidebar.tsx:92` which uses the same approach. Kept for consistency. The Cookie Store API could be adopted project-wide in a future task.

3. **P6-T05 integration:** The `ModelSelector` component expects `selectedModelId`, `onModelChange`, and `models` props. The parent (ChatHeader, wired in P6-T05) should:
   - Pass `models` from server page props (fetched via `getAvailableModels()`)
   - Pass `selectedModelId` from chat session context or `getDefaultModel()`
   - Handle `onModelChange` for any reactive state updates (persistence is handled internally)

4. **Dynamic discovery support:** The component renders any `ModelMetadata[]` passed to it, including dynamically discovered models from OpenRouter. No hardcoded model list — fully driven by the `models` prop.
