**Plan said:** Copy ~32 files including alert.tsx, checkbox.tsx, command.tsx, dialog.tsx, button-group.tsx, input-group.tsx, popover.tsx, tabs.tsx, toggle.tsx, toggle-group.tsx, visually-hidden.tsx.
**What was done:** Copied the 22 files that actually exist in `oldapp/components/ui/`. The ~10 files listed in the spec (alert.tsx, checkbox.tsx, command.tsx, dialog.tsx, button-group.tsx, input-group.tsx, popover.tsx, tabs.tsx, toggle.tsx, toggle-group.tsx, visually-hidden.tsx) do not exist in the source.
**Why:** The plan overestimated the file count. We copy what exists — creating non-existent components from scratch is out of scope. Note: the source has `alert-dialog.tsx` (not `alert.tsx`).
**Trade-offs:** If downstream tasks need the missing components, they'll need to be created at that point.

### 2. ChatSDKError → plain Error

**Plan said:** Only change import paths, not component logic.
**What was done:** Replaced `ChatSDKError` from `@/lib/errors` (old app's error class) with plain `new Error("descriptive message")` in carousel.tsx and sidebar.tsx.
**Why:** `ChatSDKError` does not exist in the new project. The new project uses `AppError` from `@/lib/errors/app-error` with a typed `ErrorCode` system that doesn't include UI context error codes like `"bad_request:ui:useCarousel_outside_provider"`. These are purely development-time errors for hook-outside-provider detection — they don't need structured error handling. Plain `Error` is the standard pattern for React context validation.
**Trade-offs:** None meaningful. These errors only fire during development if a hook is called outside its provider.
