## Architectural Deviation

### `'use cache'` cannot be applied inside a generic wrapper

- **Original design**: Task spec called for `withCache<T>(tag, fetcher, life?)` that internally applies the `'use cache'` directive.
- **What was done**: `withCache` applies `cacheTag` + `cacheLife` + calls the fetcher, but the caller must declare `'use cache'` at their own function scope.
- **Why**: The `'use cache'` directive must be the first statement in a function body, and all function arguments must be serializable for cache key generation. A `fetcher: () => Promise<T>` is a function reference — not serializable — so placing `'use cache'` inside `withCache` would cause a runtime error. The task spec anticipated this: _"If wrapping is not possible due to directive constraints, create helper utilities that document the pattern for consumers instead."_
- **Trade-offs**: Consumers write one extra line (`'use cache'` in their function), but get full type safety and correct cache behavior. The `withCache` helper still reduces boilerplate by combining `cacheTag` + `cacheLife` + fetcher invocation in a single call.

### `cacheLife` overload resolution requires type assertion

- **Issue**: The `.next/dev/types/cache-life.d.ts` module augmentation overrides `next/cache` and removes the generic `cacheLife(profile: string)` overload, leaving only per-preset literal overloads. TypeScript cannot resolve a union of literals (`CacheLifePreset`) against individual literal overloads.
- **Fix**: Used `life as CacheLifePreset & "default"` assertion in the internal `applyCacheLife` dispatcher. This is safe because our `CacheLifePreset` type already constrains values to valid presets at compile time.

## Consumer Pattern

```typescript
import { withCache } from '@/lib/cache/with-cache'
import { cacheKeys } from '@/lib/cache/keys'
import { getChatById } from '@/lib/data/chat'

// Pattern A: withCache (wraps fetcher call)
export async function getCachedChat(chatId: string) {
  'use cache'
  return withCache(cacheKeys.chat(chatId), () => getChatById(chatId), 'seconds')
}

// Pattern B: applyCacheConfig (inline fetch logic)
export async function getCachedModels() {
  'use cache'
  applyCacheConfig(cacheKeys.models(), 'hours')
  const models = await fetchModelsFromProviders()
  return models
}
```
