## Findings

1. **`router.refresh()` for model propagation:** The `ChatSessionValue.chatModel` is derived from `initialChatModel`, which comes from server page props (cookie-based). There is no `setChatModel` setter in the context. Using `router.refresh()` after model selection causes the server to re-read the cookie and provide the updated model as a new prop, which flows through to `useChatSession` → transport memo. This is the correct approach given the server-first architecture. For a future optimization, a `setChatModel` state field could be added to `ChatSessionValue` for instant client-side model switching without a server round-trip.

2. **Persistence handled by ModelSelector:** The `ModelSelector` component (P6-T04) internally calls `persistModelSelection()` which writes both cookie and localStorage. The `onModelChange` callback in `ChatHeader` does NOT need to handle persistence — it only triggers `router.refresh()` for server state consistency.
