## Summary

Created three chat server actions following the ActionResult<T> pattern: `deleteChat`, `deleteAllChats`, and `deleteTrailingMessages`. All validate session via `getAppSession()`, use Zod schemas for input validation, perform ownership checks where applicable, call `lib/data/` functions for data access, and use `invalidate*()` wrappers from `lib/cache/revalidate.ts` for cache invalidation via `updateTag`.

## Files Changed

- `features/chat/actions/delete-chat.ts` — created: Server action that deletes a single chat (with ownership check) and invalidates user's chat list cache
- `features/chat/actions/delete-all-chats.ts` — created: Server action that deletes all chats for the current user and invalidates chat list cache
- `features/chat/actions/delete-trailing-messages.ts` — created: Server action that deletes a target message and all subsequent messages (by createdAt) within a chat, with ownership check, and invalidates the specific chat cache

## Design Decisions

- **deleteChat** invalidates `chats:{userId}` (via `invalidateChatList`) per the revalidation matrix in patterns.md §9. Does NOT invalidate `chat:{chatId}` since the chat no longer exists.
- **deleteAllChats** takes no input — operates on the authenticated user's session. No Zod schema needed since there's no external input.
- **deleteTrailingMessages** reuses `deleteMessagesSchema` from `features/chat/schemas/chat.schema.ts` (P3-T05). Invalidates `chat:{chatId}` per the revalidation matrix. Includes ownership check on the parent chat.
- All actions return `ActionResult<void>` — never throw. Errors from data layer calls are caught and mapped to structured error responses.
- All actions follow the Auth → Validate → Authorize → Execute pattern from patterns.md §2.
