## Deviations

**ChatStreamProvider not rendered inside ChatShell.**

- **Plan said:** ChatShell wraps children in `ChatSessionContext.Provider → ChatStreamProvider`.
- **What was done:** ChatShell only wraps children in `ChatSessionContext.Provider`. ChatStreamProvider is NOT rendered by ChatShell — it's an ancestor provided at page level.
- **Why:** `useChatSession` (called at the top of ChatShell) internally calls `useChatStreamDispatch()`, which requires `ChatStreamProvider` to already exist as an ancestor. Rendering ChatStreamProvider as a child would put it below the hook call that depends on it, causing a missing-context crash. The component-wiring.md canonical doc confirms ChatStreamProvider is page-scoped, wrapping ChatShell from above.
- **Trade-offs:** None. This matches the canonical architecture in `plan/integration_map/component-wiring.md`. Pages (P3-T25) must render `<ChatStreamProvider>` wrapping `<ChatShell>`.

**StreamBridge rendered inside ChatShell (not as sibling).**

- **Plan (component-wiring.md) said:** StreamBridge is a sibling of ChatShell at page level.
- **What was done:** StreamBridge is rendered as a child of ChatShell, inside `ChatSessionContext.Provider`.
- **Why:** Task spec (P3-T21) explicitly requires ChatShell to render StreamBridge. StreamBridge only needs `useChatStream` (from ancestor ChatStreamProvider) and doesn't use ChatSessionContext, so it works in both positions. Placing it inside ChatShell keeps the orchestrator self-contained and reduces wiring in the page component, matching the task's design intent.
- **Trade-offs:** StreamBridge will re-render when ChatSessionContext value changes (though it never reads it). Negligible cost since StreamBridge renders null.

## Findings

- **P3-T25 page wiring:** Chat pages must render `<ChatStreamProvider>` wrapping `<ChatShell>` as shown in component-wiring.md. The page (not ChatShell) owns the ChatStreamProvider boundary.
- **P4-T17 wiring points:** Two noop callbacks need real implementations: (1) `handleArtifactDelta` in ChatShell → `artifactStore.setState`, (2) `onChatChange` in `useChatSideEffects` → `artifactStore.reset`.
- **P5-T02 wiring points:** `useChatSession` accepts optional `onNewChat` and `onTitleUpdate` callbacks. ChatShell currently doesn't pass them — P5-T02 will wire these for PendingChatsProvider integration.
