## Summary

Created the multimodal input component and submit button for the chat interface. MultimodalInput reads all state from ChatSessionContext (zero prop drilling), features auto-resizing textarea, file attachment via button/drag-and-drop/clipboard paste, Enter-to-submit with Shift+Enter for newline, and a stop button during generation. SubmitButton is extracted as a separate component with send/stop states and tooltips.

## Deviations

1. **Outer element is `<form>` instead of `<div>`**: The spec doesn't prescribe the wrapper element. Using `<form>` satisfies biome's `noStaticElementInteractions` lint rule (div with drag-and-drop handlers triggers a11y lint error) and is semantically correct since this is an input form. Also provides native `onSubmit` for form submission.

2. **Auto-resize via onChange handler instead of useEffect**: Biome's `useExhaustiveDependencies` flagged the `input` dependency in a useEffect (since `input` isn't read directly in the effect body, only indirectly via scrollHeight). Moved resize logic to the onChange handler which receives the native DOM event target with the already-updated value — simpler, no effect needed.

3. **Inline attachment preview instead of PreviewAttachment component**: The `preview-attachment.tsx` component from the conventions directory structure doesn't exist yet and isn't part of this task. Used minimal inline pill-style attachment previews. PreviewAttachment can be created separately and wired in later.

4. **No localStorage persistence for input**: The old app persisted input to localStorage with debounce. This adds complexity (~20 extra lines) without being part of the acceptance criteria. Can be added as an enhancement.

## Findings

- **D015 confirmed**: AI SDK doesn't export Attachment type. Used the `Attachment` interface defined in `features/chat/types/chat.types.ts` (P3-T05) as specified.
- **Upload API dependency**: The component calls `/api/files/upload` which doesn't exist yet. This is listed in the conventions directory structure and will be created in a future task. Component compiles and is structurally correct.
- **`sendMessage` contract**: `ChatSessionValue.sendMessage` takes an optional `{ preventDefault?: () => void }` parameter. The component calls it with no args (form submit prevention is handled by the form's onSubmit handler).
