Wired file upload functionality into `MultimodalInput` component: added `PreviewAttachment` thumbnail previews, abort-on-unmount for active uploads, `accept="image/*"` on file input, AbortError handling in fetch calls, and signal propagation through upload helpers.

  - Added `PreviewAttachment` import from `./preview-attachment`

  - Added `AbortError` handling in `uploadFile()` catch block (silently ignores aborted uploads)
  - Added `uploadAbortRef` (AbortController ref) with `useEffect` cleanup that aborts on unmount
  - Updated `handleFileChange`, `handlePaste`, `handleDrop` to create AbortController and pass signal

  - Added `accept="image/*"` to hidden file input
  - Changed `aria-label` from "Upload attachments" to "Upload file"

## Deviations

1. **aria-label value**: Spec said `aria-label="Upload file"`. The previous implementation used `"Upload attachments"`. Changed to match spec exactly. The attachment button itself retains `aria-label="Attach file"` which is a distinct element.

2. **Attachment-to-message-parts conversion**: The spec required "on submit: convert attachments to message parts". This was already implemented in `use-chat-session.ts` `sendMessage()` callback (converts `attachments` state → `FileUIPart[]` before calling SDK `sdkSendMessage`). No change needed in `multimodal-input.tsx` since the context layer handles it.

3. **Clear attachments after submit**: Already handled by `sendMessage()` in `use-chat-session.ts` which calls `setAttachments([])` after submission. No duplicate clearing needed.

## Findings

- The `sendMessage` in `use-chat-session.ts` (P3-T11) already handles attachment-to-message-part conversion and post-submit cleanup. Future tasks should be aware that the chat session hook is the canonical location for submit logic, not the input component.
- The `uploadFile` and `processFiles` are module-level functions (not component methods), making AbortController threading require explicit `signal` parameter passing rather than ref access.
