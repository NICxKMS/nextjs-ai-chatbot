## Design Decisions

- **Parallel queries for getChatWithMessages**: Used `Promise.all` to run chat + messages queries concurrently rather than a JOIN. This is cleaner (no denormalization/reshaping) and more efficient than sequential queries. Drizzle relations would enable `with: { messages: true }` but aren't defined in the schema yet.
- **FK cascade for deletes**: The schema defines `onDelete: "cascade"` on all child FK columns (messages.chatId, votes.chatId, artifacts.chatId). A single `DELETE FROM Chat WHERE id = ?` cascades to all children. No transaction or manual multi-table delete needed — simpler and atomic at the DB level.
- **Cursor via chat ID**: The cursor is a chat ID. On pagination, we look up the cursor chat's `updatedAt` and use `lt(updatedAt, cursorDate)` for the next page. This matches the existing PaginationParams contract (`{ cursor?: string; limit?: number }`).
- **Default page size**: 20 items, consistent with typical sidebar pagination.
