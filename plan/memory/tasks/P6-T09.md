## Deviations

1. **Rate limiting approach**: The task spec references `requireRateLimitForRoute` (from oldapp's guard pattern). The new codebase has no such abstraction — instead, rate limiting uses the Redis `incr`/`expire` primitives from `lib/cache/client.ts` with keys from `lib/cache/keys.ts`. Implemented rate limiting inline in the route handler using these existing primitives with graceful degradation (allows upload if Redis unavailable). This is simpler and consistent with how `rateLimitKeys` is structured in the new codebase.

2. **Error code surface**: Old app used `ChatSDKError` with string codes like `bad_request:api:storage_not_configured`. New app uses `AppError` with typed `ErrorCode` union. Added only the error codes needed for file upload validation (file_too_large, file_type_unsupported, no_file_uploaded) and rate limiting (rate_limit:upload:too_many_requests) to the typed union, keeping the error surface minimal and type-safe.

3. **BLOB_READ_WRITE_TOKEN check**: Old app explicitly checked for `BLOB_READ_WRITE_TOKEN` env var. Omitted this check since `@vercel/blob`'s `put()` will throw if the token is missing, and the catch block handles that uniformly. Avoids coupling route logic to specific env var names.
