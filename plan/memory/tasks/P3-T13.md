## Deviations

1. **createArtifact/updateArtifact are NOT stubs** — The task spec described createArtifact as a "STUB" and updateArtifact as a "STUB for P4", but since all required dependencies exist (handler registry, data layer, stream writer types), both tools are fully wired to the handler registry via `getArtifactHandler()`, call `handler.create()`/`handler.update()`, persist via `saveArtifactVersion()`, and write all expected data stream parts. They will naturally fail at runtime if no handlers are registered (which happens in P4), but the tool code itself is complete — no stub return values. This is better than shipping dead code that must be rewritten.

2. **Weather tool supports city names** — The task spec said "Zod schema (latitude, longitude)" but the oldapp reference implementation supports both coordinates and city-name lookup via geocoding. Implemented as a `z.union([coordinates, city])` for behavioral parity with the reference. This is strictly backward-compatible.

3. **AI SDK uses `inputSchema` not `parameters`** — The migration guide code sketches used `parameters` but the actual AI SDK v4 `tool()` function requires `inputSchema`. Used the correct AI SDK API.

## Findings

1. **Handler registration dependency** — createArtifact and updateArtifact will throw at runtime until P4 registers handlers via `registerArtifactHandler()`. This is expected and documented in the handler registry module.

2. **ArtifactStreamWriter interface** — The `chatStream.writeData({ type, content })` interface from `ArtifactStreamWriter` uses `content` (not `data`), unlike the oldapp which used `dataStream.write({ type, data, transient })`. The API route (P3-T23) must provide an adapter that bridges the actual stream writer to this interface.

3. **Suggestion schema field names differ from oldapp** — The oldapp uses `originalSentence`/`suggestedSentence` in the AI schema but maps to `originalText`/`suggestedText` for DB storage. The new implementation uses `originalText`/`suggestedText` directly in the AI schema to match the canonical `ArtifactSuggestion` type, eliminating the mapping step.

4. **Tool exports are individual, not a toolsMap** — Each file exports its tool/factory individually. The API route (P3-T23) will compose them into a tools object. This is cleaner than a single `toolsMap` export since 3 of 4 tools are factories requiring runtime params.
