## Findings

- **Stable actions pattern:** `useArtifact()` extracts `setArtifact`/`resetArtifact` as a module-level `stableActions` constant (same as `use-settings.ts`'s `actions` pattern) to avoid object allocation per render. Downstream consumers (P4-T11, P4-T12) can safely destructure `{ setArtifact }` without causing child re-renders.
- **Selector equality via `Object.is`:** `useArtifactSelector` uses `Object.is` (same semantics React uses internally) for the equality check. This means primitive selectors like `s => s.isVisible` work perfectly, but object-returning selectors like `s => ({ title: s.title, kind: s.kind })` will re-render every time since a new object is created. Consumers needing multiple fields should use `useArtifact()` instead or call `useArtifactSelector` multiple times for individual primitives.
- **Snapshot caching for contract compliance:** Added `prevSnapshotRef` to the selector hook so that repeated `getSnapshot` calls between store updates always return the exact same reference. This satisfies `useSyncExternalStore`'s contract and prevents React from raising consistency warnings with object-returning selectors.
- **SSR safety:** `useArtifactSelector`'s `getServerSnapshot` applies the selector to `initialArtifactData` (imported from artifact types), ensuring server-rendered HTML is deterministic and hydration-safe.
