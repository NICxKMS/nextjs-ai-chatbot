## Deviations

### 1. `maxSteps` → `stopWhen: stepCountIs(5)`

- **Plan said:** Use `maxSteps: 5` in streamText options
- **What was done:** Used `stopWhen: stepCountIs(5)` with import from `ai`
- **Why:** AI SDK v5 removed the `maxSteps` property from `streamText`. The replacement API is `stopWhen: stepCountIs(N)` which is a function-based approach. TypeScript compilation fails with `maxSteps`.
- **Trade-offs:** None — this is the direct 1:1 replacement.

### 2. Fixed `provider-options.ts` — `maxTokens` → `maxOutputTokens`

- **Plan said:** P3-T02 created `provider-options.ts` with `maxTokens` field in `ProviderOptionsResult`
- **What was done:** Renamed field to `maxOutputTokens` in both the interface and function body
- **Why:** AI SDK v5 `CallSettings` uses `maxOutputTokens`, not `maxTokens`. The spread `...providerOpts` into `streamText()` would silently drop the setting since `maxTokens` is not a valid key in v5 CallSettings.
- **Trade-offs:** None — bug fix. The old field name caused max tokens settings to be silently ignored.

### 3. Fixed `provider-options.ts` — `providerOptions` type

- **Plan said:** `providerOptions?: Record<string, Record<string, unknown>>`
- **What was done:** Changed to `Record<string, Record<string, JSONValue>>` with `import type { JSONValue } from "ai"`
- **Why:** AI SDK v5's `SharedV2ProviderOptions` expects `Record<string, Record<string, JSONValue>>`. `unknown` is not assignable to `JSONValue`, causing a compile error when spreading providerOpts into `streamText()`.
- **Trade-offs:** None — narrower type is more correct and matches the SDK contract.

## Findings

### AI SDK v5 Breaking Changes Discovered

1. **`maxSteps` removed** — replaced by `stopWhen: stepCountIs(N)` function. Any future task using `maxSteps` (including specs written from old docs) needs this substitution.
2. **`maxTokens` → `maxOutputTokens`** in `CallSettings`. Any code using `maxTokens` as a spread key for streamText/generateText will silently fail.
3. **`providerOptions` requires `JSONValue` values** — `unknown` is not assignable. Any typed wrapper around providerOptions must use `Record<string, Record<string, JSONValue>>`.

These findings affect any task that constructs arguments for `streamText()` or `generateText()`.
