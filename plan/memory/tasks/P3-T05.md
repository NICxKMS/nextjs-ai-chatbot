## Deviations

### DEV-1: ChatStatus imported from AI SDK instead of custom 5-value union

- **Plan says:** `ChatStatus = 'idle' | 'submitted' | 'streaming' | 'error' | 'ready'` (5 values, shared-types.md § 10)
- **Done instead:** Imported `ChatStatus` from `ai` SDK which defines `'submitted' | 'streaming' | 'ready' | 'error'` (4 values, no 'idle')
- **Why:** The AI SDK's `ChatStatus` does not include 'idle' — 'ready' serves as both the initial and completed state. Defining a custom 5-value type would create a mismatch with `useChat`'s return type, requiring the `useChatSession` hook (P3-T11) to perform unnecessary state mapping. Using the SDK type directly ensures type compatibility and avoids confusion about when 'idle' vs 'ready' applies.
- **Trade-off:** Consumers cannot check `status === 'idle'` — they should check `status === 'ready'` for the "ready to send" state instead.

### DEV-2: error field uses `Error | undefined` instead of `Error | null`

- **Plan says:** `error: Error | null` (shared-types.md § 10)
- **Done instead:** `error: Error | undefined`
- **Why:** The AI SDK's `useChat` hook returns `error: Error | undefined` (not null). Using undefined matches the SDK convention and avoids null↔undefined conversion in `useChatSession` (P3-T11). This is the standard TypeScript convention for optional values.
- **Trade-off:** Consumers should check `error !== undefined` or just `if (error)` rather than `error !== null`.

### DEV-3: Uses UIMessage from AI SDK instead of Message

- **Plan says:** `import type { Message, Attachment } from 'ai'`
- **Done instead:** `import type { UIMessage } from 'ai'` — `Attachment` defined locally
- **Why:** The AI SDK exports `UIMessage` (not `Message`) and does not export `Attachment`. `UIMessage` is the correct type for the chat message list. `Attachment` is a UI concept defined locally per the old app's pattern.

## Findings

### FIND-1: AI SDK does not export Attachment type

The `ai` package does not export an `Attachment` type. The old app defined this locally. I defined `Attachment` as a local interface in `chat.types.ts` matching the old app's shape (`name`, `url`, `contentType`). Consumers of P3-T18 (MultimodalInput) should import `Attachment` from `features/chat/types/chat.types.ts`.

### FIND-2: ChatStatus 'idle' state does not exist in AI SDK

The `useChat` hook uses 'ready' as its initial and completion state. Any P3 task referencing an 'idle' status check should use 'ready' instead. Affects: P3-T10 (ChatStreamProvider), P3-T11 (useChatSession), P3-T21 (ChatShell).
