## Summary

Created `lib/data/vote.ts` with three exported functions for vote data access:

- `getVotesByChatId(chatId, userId)` — returns `Vote[]`, filters by both chatId and userId
- `upsertVote(data)` — returns `Vote`, uses `onConflictDoUpdate` on composite PK `[chatId, messageId, userId]`
- `deleteVotesByChatId(chatId, userId)` — returns `void`, deletes by chatId+userId

## Design Decisions

- `upsertVote` uses Drizzle's `.onConflictDoUpdate()` targeting the composite PK — atomic, race-condition safe (matches oldapp pattern)
- `upsertVote` adds a row-existence guard after `.returning()` since Drizzle types the destructured result as potentially `undefined`
- Module is DB-only and session-agnostic — receives only IDs, no auth imports, no cache imports
- `getVotesByChatId` takes `userId` parameter per spec — scoped to a single user's votes (not all votes for a chat)
