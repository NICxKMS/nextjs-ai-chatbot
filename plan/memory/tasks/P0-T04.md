## Deviations

- **`process.env.DATABASE_URL!` → runtime guard**: The task spec showed `process.env.DATABASE_URL!` (non-null assertion) in client.ts. Biome's `noNonNullAssertion` rule flags this. Instead, added an explicit `if (!process.env.DATABASE_URL) throw new Error(...)` guard. This is safer (fails fast with a clear message) and lint-clean.
- **Table export names use plural**: Old app used singular (`user`, `chat`, `message`, `vote`, `document`, `suggestion`). New schema uses plural (`users`, `chats`, `messages`, `votes`, `artifacts`, `suggestions`) for clarity and convention alignment. The PG table names remain unchanged (e.g., `"User"`, `"Chat"`).
- **`chat.lastContext` replaced with `chat.model`**: Per data-flows.md CONF-013/SOFT-009, the `lastContext` jsonb column was replaced with a `model` text column.

## Findings

- **P0-T05 dependency**: `lib/types/models.types.ts` in P0-T05 will use `InferSelectModel` / `InferInsertModel` from these schema tables. The plural export names (`users`, `chats`, etc.) should be used: e.g., `InferSelectModel<typeof users>`.
- **Old app type exports removed**: The old schema exported inline types (`User`, `Chat`, `DBMessage`, etc.) directly from schema.ts. Per the plan, those Drizzle-inferred types move to `lib/types/models.types.ts` in P0-T05, keeping schema.ts focused on table definitions only.
- **Biome semicolons**: Biome is configured for `"semicolons": "asNeeded"` — the formatter removed all trailing semicolons from the created files. This is expected behavior.
