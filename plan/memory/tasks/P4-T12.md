## Deviations

**ArtifactActions receives `actions` prop instead of looking up `artifactDefinitions`**

- **Plan/old app:** Old app had `ArtifactActions` look up `artifactDefinitions.find(d => d.kind === artifact.kind)` internally to get actions per kind
- **What was done:** Component receives `actions: ArtifactAction[]` as a prop from the parent (ArtifactPanel)
- **Why:** The new architecture doesn't use an `artifactDefinitions` array — it uses a handler registry (`getArtifactHandler`). The actions are handler-specific metadata that the panel resolves and passes down. This keeps ArtifactActions as a pure display component with no knowledge of the handler registry, improving separation of concerns.
- **Trade-offs:** Parent must supply the actions array; slightly more prop drilling but cleaner component boundary.

**ArtifactCloseButton does not reset full state — visibility toggle only**

- **Plan/old app:** Old app close button conditionally reset to `initialArtifactData` when not streaming
- **What was done:** Always sets `isVisible: false` only (pure visibility toggle)
- **Why:** Per spec — "Reset handled by chat lifecycle events per state-management/streaming specs". The redesign explicitly separates close (visibility) from reset (lifecycle). This is not a deviation from the redesign spec, but it IS a deviation from oldapp behavior.

**ArtifactToolResult does not include ArtifactPreview inline**

- **Plan:** Spec says "wraps ArtifactPreview for inline preview"
- **What was done:** Simple clickable card without embedded ArtifactPreview, matching the old app's DocumentToolResult behavior
- **Why:** ArtifactPreview (P4-T14) is a separate component that fetches artifact data and renders mini editors. Embedding it in every tool result card in the message stream would cause excessive data fetching (one SWR call per visible tool result). The old app's DocumentToolResult also didn't embed a preview — it showed a simple clickable card. The ArtifactPreview component exists for a different integration point (direct inline previews). If preview integration is desired later, it can be added as an enhancement.
- **Trade-offs:** Simpler, more performant, matches proven old app pattern. ArtifactPreview can be composed in by the consumer (message.tsx) if needed.
