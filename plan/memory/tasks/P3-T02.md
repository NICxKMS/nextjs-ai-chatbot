## Summary

Created `lib/ai/prompts.ts` and `lib/ai/provider-options.ts`. The prompts module exports `composeSystemPrompt()` that assembles a system prompt from base identity, date context, optional user system prompt, and conditional artifact/tool instructions. The provider-options module exports `getProviderOptions()` that builds `streamText`-compatible options from user settings with per-provider reasoning config.

## Files Changed

- `lib/ai/prompts.ts` — created with `composeSystemPrompt()`, `CODE_PROMPT`, `SHEET_PROMPT`, `getUpdateArtifactPrompt()`. All tool references use `createArtifact`/`updateArtifact`. Zero "document" references (except adjective "Documented" in code prompt).
- `lib/ai/provider-options.ts` — created with `getProviderOptions(modelId, settings)`. Returns `ProviderOptionsResult` with temperature, topP, maxTokens, and per-provider reasoning providerOptions (Google thinkingBudget, OpenAI reasoningEffort, Anthropic via OpenRouter thinkingBudget).

## Deviations

1. **Redesign code sketch used `settings.reasoningBudget` / `settings.reasoningEffort`** — these fields don't exist in `SettingsState`. Per Wave 4 decision (AI-W2-01 in `ai-sdk-usage.md`), reasoning config uses hardcoded defaults gated by `enableReasoning: boolean`: Google→1024, OpenAI→"medium", Anthropic→8000. This matches the planned approach.

2. **Added Anthropic via OpenRouter reasoning config** — the redesign only showed Google and OpenAI. Added `openrouter:anthropic/*` prefix matching since Claude 3.7 Sonnet is in the static catalog with `supportsReasoning: true`. Trade-off: slightly more code, but ensures reasoning works across all supported providers.

3. **`getUpdateArtifactPrompt` uses `"text artifact"` fallback** instead of `"document"` — per naming constraint, no "document" in prompt text.

## Findings

1. **Consumer: P3-T23 (chat API route)** — `composeSystemPrompt` is consumed by the chat API route. It needs to pass `hasTools` based on `model.supportsToolCalling` and `supportsReasoning` from `ModelMetadata`. The route should spread `getProviderOptions()` result into `streamText()`.

2. **Consumer: P4 artifact handlers** — `CODE_PROMPT`, `SHEET_PROMPT`, and `getUpdateArtifactPrompt()` are exported for use by artifact tool implementations and handler create/update methods in P4.

3. **ProviderOptionsResult type** — exported as a named interface so P3-T23 can use it for type safety when spreading into `streamText()`.
