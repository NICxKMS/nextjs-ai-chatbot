- **Route classification:** `classifyRoute()` function implementing the canonical matrix:
  - `public`: `/login`, `/register`, `/api/health` — skip auth entirely
  - `guest-eligible`: `/`, `/chat/*`, `/api/*` — auto-bootstrap guest if no session
  - `auth-required`: all other routes — redirect to `/login` if no valid session
- **Rate-limit-exempt:** `isRateLimitExempt()` for `/_next/*`, `/favicon.ico`, `/images/*`, `/api/health`
- **Guest token lifecycle (dual-write pattern):**
  - No tokens → `mintGuestToken(guest:<uuid>)` + dual-write (`request.cookies.set` + `response.cookies.set`)
  - Valid token near expiry → `rotateGuestToken()` + dual-write if rotated
  - Invalid/expired token → mint fresh token with new identity + dual-write
- **Auth redirect:** Only when route class is `auth-required` AND no `sb-access-token` AND no `guest_token`
- **Rate limiting:** Stub with TODO(P6) — log only, does not block
- Cookie options: `{ httpOnly, secure: production, sameSite: 'lax', maxAge: 7d, path: '/' }`

**Auth redirect bypass note:** The proxy checks cookie *presence* (not validity) for the auth-required redirect. An expired `sb-access-token` or `guest_token` cookie bypasses the proxy redirect, but `getAppSession()` returns `null` server-side. This is by design per auth-system.md: "non-guest enforcement remains in route/action guards." Pages on auth-required routes must still call `getAppSession()` and handle null. This is a lightweight-edge-check + deep-validation architecture — acceptable and documented.
