## Summary

Wired the voting system into the chat page using VotesProvider + VoteResolver pattern with React 19 `use()` for deferred vote data. VoteButtons render on assistant messages via message-actions.tsx, reading vote data from VotesProvider context through `useVoteForMessage` hook.

- `features/chat/components/message-actions.tsx` — **modified** — Replaced placeholder vote buttons with VoteButtons from voting feature, wired via useVoteForMessage
- `app/(chat)/chat/[id]/page.tsx` — **modified** — Wrapped ChatShell in VotesProvider, added VoteResolver in Suspense, activated votesPromise with error containment

## Work Performed

### vote-resolver.tsx (NEW)
- **VotesProvider**: Wraps ChatShell at page level, holds server votes state (initially empty), uses `useVotes(chatId, serverVotes)` internally for optimistic state management. Exposes votes + submitVote through React Context. Two split contexts: internal VotesSetterContext (for VoteResolver to write) and public VotesContext (for consumers to read).
- **VoteResolver**: Resolves `votesPromise` via React 19 `use()` inside Suspense. Sets resolved votes into VotesProvider state via useEffect. Vote fetch failures caught at promise level (`.catch()`) before reaching VoteResolver.
- **useVoteForMessage(messageId)**: Returns `{ vote, submitVote }` from VotesProvider context. Gracefully degrades outside VotesProvider (returns `{ vote: undefined, submitVote: noop }`) — safe for new chat page where VotesProvider is not mounted.

## Deviations

**VoteButtons rendered in `message-actions.tsx` instead of `message.tsx`**

- **Spec said:** Render VoteButtons in `features/chat/components/message.tsx`
- **What was done:** Rendered VoteButtons in `features/chat/components/message-actions.tsx`
- **Why:** `message.tsx` (ChatMessage component) renders message *content* (text, tools, reasoning). Action buttons (copy, edit, vote) are rendered in `message-actions.tsx` (MessageActions component), which already contained placeholder vote buttons with TODO comments from P3-T15. Putting vote buttons in the content component would break the content/actions separation and create an inconsistent layout. MessageActions is the correct architectural location.
- **Trade-offs:** The spec's allowlist entry `message.tsx -> vote-buttons.tsx` is no longer needed (but kept for reference). Two new allowlist entries were added for message-actions.tsx.
