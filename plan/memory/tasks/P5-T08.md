## Deviations

**Over-fetch implementation:** The spec says "fetches 21, slices to 20" but `getChatsByUserId` (P1-T06) already implements the over-fetch pattern internally — it fetches `limit + 1` rows and returns a `hasMore` boolean. Duplicating this by passing `limit: 21` would cause a wasteful double-overfetch (22 rows from DB). Instead, `getCachedChats` passes `limit: 20` and uses the returned `hasMore` directly. The observable behavior is identical: 20 chats returned with a correct `initialHasMore` flag. This is simpler, avoids redundant DB work, and reuses the existing pagination abstraction.
