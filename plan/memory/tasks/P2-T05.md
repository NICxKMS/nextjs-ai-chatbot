## Findings

- **`useActionState` generic params:** React 19 `@types/react@19.2.7` has two overloads for `useActionState` — one with `<State>` (no payload) and one with `<State, Payload>`. When specifying only the `<State>` generic, TypeScript matches the no-payload overload, causing a type error. Must always provide both generics: `useActionState<AuthFormState | null, FormData>(...)`.
- **Server action redirect handling:** The `login`/`register` server actions call `redirect()` on success, which is handled transparently by Next.js when invoked through `useActionState`'s form action. The wrapped `handleAction` never returns a value after a successful server action because the redirect interrupts the flow. This means the `success: true` branch in the form state is effectively unreachable, but the types must still account for non-redirect `ActionResult<void>` returns for correctness.
