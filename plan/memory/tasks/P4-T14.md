## Deviations

### `UIArtifact` type extended with `boundingBox`

- **What the plan said:** P4-T14 spec says "calls `setArtifact({artifactId, isVisible: true, boundingBox})`" — implying `boundingBox` is part of `UIArtifact`.
- **What existed:** `UIArtifact` in `lib/types/artifact.types.ts` had no `boundingBox` field (the P4-T01 types task did not include it).
- **What was done:** Added `BoundingBox` type and optional `boundingBox?: BoundingBox` field to `UIArtifact`. This is necessary for the preview → panel animation to work as specified.
- **Why:** Without this field, `setArtifact` cannot carry bounding box data to the artifact panel. The old app (`oldapp/hooks/use-artifact.ts:15`) included `boundingBox` in their artifact type. The field is optional so it doesn't break any existing consumers.
- **Trade-offs:** Modifies a shared type in `lib/types/`. All existing callers of `setArtifact` are unaffected since the field is optional.

### `isReadonly` prop removed

- **What the old app had:** `DocumentPreview` accepted an `isReadonly` prop to show toast errors for shared chats.
- **What was done:** Removed `isReadonly` from the component props since the shared-chat read-only feature isn't implemented in this phase and the prop was unused.
- **Why:** Biome lint flagged unused function parameter. The prop can be added back when shared chat read-only mode is implemented.

## Findings

### P4-T11 needs to read `boundingBox` from artifact store

The artifact panel (P4-T11) will need to read `artifact.boundingBox` for the AnimatePresence origin animation. The `BoundingBox` type is now exported from `@/lib/types/artifact.types.ts` and available on `UIArtifact.boundingBox`.

### Editor prop signatures vary

The four editors have different `save` callback signatures:
- `TextEditor.onSaveContent: (content: string, debounce: boolean) => void`
- `CodeEditor.onSaveContent: (content: string, debounce: boolean) => void`
- `SheetEditor.saveContent: (content: string, isCurrentVersion: boolean) => void`
- `ImageEditor` — no save callback

This divergence required two separate noop stubs. Future consolidation could standardize the save interface.

### `ImageEditor` doesn't accept `currentVersionIndex`

Unlike the other three editors, `ImageEditor` has no `currentVersionIndex` prop. The preview passes only the props each editor actually accepts.
