## Deviations

**Slider component used instead of number inputs for temperature/topP:**
- The old app (`oldapp/components/settings/settings-sheet.tsx`) used `<Input type="number">` for temperature and topP.
- The new implementation uses the `<Slider>` component from `components/ui/slider.tsx` for temperature and topP, matching the task spec requirement ("temperature slider, topP slider").
- Better: Sliders provide a more intuitive UX for continuous bounded values; the spec explicitly called them "sliders".

**Toggle implementation uses native `<Switch>` instead of custom button toggle:**
- The old app used a custom `<Button>` styled as a toggle with "On"/"Off" text.
- The new implementation uses the `<Switch>` component from `components/ui/switch.tsx` (native checkbox).
- Better: Semantic HTML, accessible by default (native checkbox role), consistent with shadcn/ui library patterns.

**Controlled open/close pattern:**
- The old app bundled a `SettingsButton` trigger inside the same file.
- The new implementation accepts `open` and `onOpenChange` props, letting the parent (ChatHeader P3-T19) own the trigger.
- Better: Follows composition pattern — the panel is a pure controlled sheet, decoupled from its trigger.
