## Summary

Created explicit revalidation helper functions in `lib/cache/revalidate.ts`. Two families of wrappers: `invalidate*` (for Server Actions, calls `updateTag` for immediate consistency / read-your-own-writes) and `refresh*` (for Route Handlers, calls `revalidateTag(tag, "max")` for stale-while-revalidate). All functions take a single parameter and compose at the call site. Uses `cacheKeys` from `lib/cache/keys` for tag name consistency.

## Files Changed
- `lib/cache/revalidate.ts` — New file. Exports 8 explicit wrapper functions:
  - **Server Action helpers** (`updateTag`): `invalidateChat(chatId)`, `invalidateChatList(userId)`, `invalidateVotes(chatId)`, `invalidateArtifact(artifactId)`, `invalidateModels()`
  - **Route Handler helpers** (`revalidateTag(tag, "max")`): `refreshChat(chatId)`, `refreshChatList(userId)`, `refreshArtifact(artifactId)`

## Design Decisions
- `invalidate*` uses `updateTag()` from `next/cache` (Next.js 16 API: Server Actions only, immediate expiry, read-your-own-writes)
- `refresh*` uses `revalidateTag(tag, "max")` from `next/cache` (Next.js 16 API: stale-while-revalidate semantics)
- No `server-only` import since both `updateTag` and `revalidateTag` are inherently server-side APIs from `next/cache`
- Entity names use `artifact` (NOT `document`) throughout
