## Summary
Created two "use client" message interaction components: `MessageActions` (toolbar with Copy, Edit, Vote) and `MessageEditor` (inline editing with submit/cancel). Both read session state from `ChatSessionContext` via `useChatSessionContext()` hook.

## Files Changed
- `features/chat/components/message-actions.tsx` — created; memoized toolbar with Copy (all messages), Edit (user messages on hover), Vote up/down (assistant messages). Composes `MessageAction`/`MessageActionsContainer` primitives from `components/ai-elements/message.tsx`.
- `features/chat/components/message-editor.tsx` — created; inline textarea editor with auto-resize, submit calls `editMessage` from ChatSessionContext, cancel returns to view mode.

## Deviations
- **Vote buttons are stubs**: Task spec says "Vote buttons call saveVote server action (stub/import from lib/data/vote.ts)". Instead, vote buttons render with proper disabled/pressed states but show a toast placeholder. Reason: `lib/data/vote.ts` contains raw DB functions (not server actions), and the spec itself says "functional voting via VoteResolver wired in P6". Importing DB functions directly from a client component is architecturally wrong. The buttons are ready for P6 wiring with correct `aria-pressed`, `disabled`, and `data-testid` attributes.
- **MessageEditor uses `editMessage` from context (not `deleteTrailingMessages` directly)**: The old app's MessageEditor called `deleteTrailingMessages` + `setMessages` + `regenerate` manually. The new architecture centralizes this in `editMessage` on ChatSessionContext (implemented in `use-chat-session.ts`), which already handles delete trailing + re-submit. This is architecturally superior — single responsibility, no prop drilling of `setMessages`/`regenerate`.
- **Reused `MessageAction`/`MessageActionsContainer` primitives**: Instead of building custom action wrappers, composed existing primitives from `components/ai-elements/message.tsx` which already provide tooltip, icon sizing, and accessible button rendering.

## Findings
- `getMessageText` helper (extract text from UIMessage parts) is duplicated in both files. A shared utility in `features/chat/lib/` or `lib/utils/` would deduplicate this. Not done here to stay in scope (2 files specified). Future task or refactor could extract it.
- The `MessageAction` primitive in `components/ai-elements/message.tsx` wraps each button in its own `TooltipProvider`. If many actions render together, a single `TooltipProvider` parent would be more efficient. This is a pre-existing pattern — not introduced by this task.
