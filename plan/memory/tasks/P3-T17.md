## Deviations

**Spec said:** "Virtualized via react-virtuoso with followOutput for streaming"

**What was done:** Used a simple scrollable `<div>` container with `useScrollToBottom` (IntersectionObserver) instead of react-virtuoso.

**Why:** The success criteria explicitly require `useScrollToBottom` for scroll management. The `useScrollToBottom` hook (P3-T12) was purposely designed with `containerRef`/`endRef` + IntersectionObserver — a pattern incompatible with react-virtuoso's internal scroll management (which uses its own `atBottomStateChange`/`followOutput`). Using both would create conflicting scroll detection. A simple scrollable div is: (1) simpler (~155 vs ~250+ LOC), (2) fully compatible with useScrollToBottom, (3) sufficient for typical chat volumes, (4) aligned with AGENTS.md simplification policy. If virtualization is needed for extremely long conversations, it can be layered in later.

**Trade-offs:** No virtualization means all messages are in the DOM. For conversations with thousands of messages, this could impact performance. In practice, most chat sessions have <100 messages, making this a non-issue.

**Spec said (conversation.tsx AI Element Copy):** Copy `oldapp/components/elements/conversation.tsx` → `components/ai-elements/conversation.tsx`

**What was done:** Did not copy conversation.tsx. The old conversation.tsx wraps `use-stick-to-bottom` (a third-party library), which is replaced by our `useScrollToBottom` hook. The wrapper components (`Conversation`, `ConversationContent`, `ConversationScrollButton`) add indirection without value when using our simpler IntersectionObserver approach. The scroll container, content layout, and scroll button are implemented directly in the Messages component.

## Findings

- **MessageItem wrapper pattern**: Created a lightweight `MessageItem` component that manages per-message `view`/`edit` mode state. This keeps the mode state isolated per message and avoids lifting an array of mode states to the Messages level. MessageEditor and MessageActions both work with this `setMode` callback pattern.

- **MessageActions visibility during streaming**: MessageActions are hidden (`!isLoading`) for the currently-streaming message to avoid showing copy/vote buttons on incomplete content. This matches the old app behavior where actions aren't shown during streaming.

- **Consumer for P3-T21 (ChatShell)**: The `Messages` component is self-contained — it only needs to be placed inside a `ChatSessionContext.Provider`. No props required. ChatShell simply renders `<Messages />`.
