## Deviations

### 1. `api.types.ts` — Cursor-based pagination instead of page-based

**Task description said:** `PaginatedResult<T>` with `{ items, total, page, pageSize, hasMore }` and `PaginationParams` with `{ page, pageSize }`.

**Done instead:** Cursor-based pagination per `shared-types.md` §14: `PaginatedResult<T>` with `{ items, hasMore, nextCursor? }` and `PaginationParams` with `{ cursor?, limit? }`.

**Why:** `shared-types.md` §14 is the authoritative type contract spec. It defines cursor-based pagination, which is what the actual consumers (`GET /api/history`, `getChatsByUserId()`) will use. The task description appears to have been written against an earlier version of the spec. Cursor-based pagination is also the correct pattern for chat history (infinite scroll with cursor), not page-based.

**Trade-offs:** None — cursor-based is superior for the use case and matches the spec.

### 2. `api.types.ts` — HealthResponse uses "healthy/degraded/unhealthy" instead of "ok/degraded/error"

**Task description said:** `status: "ok" | "degraded" | "error"`.

**Done instead:** `status: "healthy" | "degraded" | "unhealthy"` per `shared-types.md` §14.

**Why:** `shared-types.md` §14 is the authoritative spec and uses `healthy/degraded/unhealthy`. The HealthResponse also includes detailed `checks` with per-subsystem status (database, cache) per the spec.

**Trade-offs:** None — follows authoritative spec.

### 3. `result.types.ts` — Uses `ErrorCode` type instead of plain `string`

**Task description said:** `error: { code: string; message: string; details?: unknown }`.

**Done instead:** `error: { code: ErrorCode; message: string }` per `shared-types.md` §2.

**Why:** `shared-types.md` §2 is the authoritative spec. Using `ErrorCode` provides type-safe error handling with the `type:surface:detail` coded errors already defined in `lib/errors/codes.ts`. Removed `details` field since the spec doesn't include it — error details are carried by `AppError.details` at the class level, not in the action result.

**Trade-offs:** Slightly more coupled (requires importing ErrorCode), but provides compile-time safety for error codes.
