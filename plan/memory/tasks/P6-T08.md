## Deviations

**Spec:** "Wire `useChatVisibility` hook (P6-T06) into SidebarHistoryItem via `onVisibilityChange` callback prop from SidebarHistoryClient."

**Done:** Called `updateChatVisibility` Server Action directly from a `useCallback` handler in `SidebarHistoryClient`, rather than using the `useChatVisibility` hook.

**Why:** `useChatVisibility` is a per-chat hook (uses `useOptimistic` for a single chat's state). It cannot be called per-item in a loop — hooks can't be called conditionally or in iterations. The `onVisibilityChange` callback pattern in `SidebarHistoryItem` expects a single function from the parent. Calling the Server Action directly is functionally equivalent and follows the same pattern as `handleDeleteConfirm` in the same component. The `useChatVisibility` hook's `useOptimistic` benefit doesn't apply here since the sidebar reads visibility from the `chat.visibility` prop (refreshed via `updateTag` revalidation after the Server Action completes).

**Trade-offs:** No per-item optimistic UI in the sidebar share submenu — visibility checkmark updates only after server revalidation. This matches the delete behavior pattern and is acceptable since the Server Action is fast.
