## Deviations

**Spec said:** Store exposes `getSnapshot`, `getServerSnapshot`, `subscribe`, `setState`, `reset` with "content accumulation: text APPEND, code/sheet REPLACE".

**What was done:** In addition to the 5 core methods, added two explicit convenience methods — `appendContent(delta)` and `replaceContent(content)` — so that StreamBridge (the primary caller for delta processing) can express intent without knowing the accumulation pattern. These methods directly mutate `state` and call `emitChange()` without going through the updater-function path of `setState`, which is marginally more efficient for the high-frequency streaming hot path (~10-20 calls/sec).

**Why:** Cleaner API boundary — StreamBridge calls `artifactStore.appendContent(delta)` instead of `artifactStore.setState(prev => ({ ...prev, content: prev.content + delta }))`. The intent is self-documenting and the delta semantics (APPEND vs REPLACE) are encapsulated in the store rather than scattered across callers.

**Trade-off:** Two extra methods on the store API. Minimal complexity increase.
