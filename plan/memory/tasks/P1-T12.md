## Summary

Created `lib/ai/provider.ts` — the `myProvider` custom provider wrapper that resolves models via the AI provider registry and applies `extractReasoningMiddleware` conditionally per model-ID prefix.

### Implementation Details

- **`myProvider`** exported via `customProvider()` from the `ai` package
- Uses `fallbackProvider` pattern to dynamically resolve all model IDs through the registry (from P1-T11)
- Reasoning middleware applied per prefix:
  - `openai:o` → `{ tagName: 'thinking' }` (o1, o3, o4-mini series)
  - `google:gemini-2.5` → `{ tagName: 'thinking' }` (Gemini 2.5 series)
  - `openrouter:deepseek/deepseek-r1` → `{ tagName: 'think' }` (DeepSeek R1)
- **No** usage tracking middleware
- **No** error wrapping middleware
- **No** logging middleware
- `textEmbeddingModel` and `imageModel` delegate directly to registry (ProviderV2 compliance)

### Design Note: `customProvider` with `fallbackProvider`

The `customProvider()` API accepts a static `languageModels` record, not a callback. Since we need dynamic model resolution with conditional middleware wrapping, the implementation uses `customProvider({ fallbackProvider: reasoningProvider })` where `reasoningProvider` is a `ProviderV2`-conformant object that wraps registry models with reasoning middleware. This satisfies the spec requirement of using `customProvider()` while enabling dynamic model resolution.

A `RegistryModelId` type alias (`\`${string}:${string}\``) bridges the plain `string` modelId from the ProviderV2 interface to the template literal type the registry expects.
