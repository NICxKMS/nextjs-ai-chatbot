## Deviations

1. **KIND_ACTIONS empty arrays**: The spec says "ArtifactActions renders correct buttons for each artifact kind." The panel passes actions from a `KIND_ACTIONS` map, but all arrays are currently empty `[]`. The `ArtifactActions` component handles this gracefully (returns null when empty). Actual per-kind action definitions will be wired in P4-T17 or a follow-up task when handlers expose their action lists. This is a structural stub — no behavior is lost since ArtifactActions already handles the empty case.

2. **No `usehooks-ts` debounce**: The old app used `useDebounceCallback` from `usehooks-ts`, which is not in the new project's dependencies. Implemented debounce with `useRef<setTimeout>` + manual cleanup. Same behavior (2000ms debounce), simpler dependency footprint.

3. **Simplified animation**: The old app had complex dual-panel animation (ArtifactMessages sidebar + editor). Per redesign AR-1, ArtifactMessages sidebar was explicitly removed. Animation simplified to: initial from bounding box (if available) → full-screen overlay. Exit scales to 0.5 with spring physics. Falls back to opacity/scale when no bounding box is present.

## Findings

1. ~~**SheetEditor has a different save callback signature**~~ **RESOLVED (Session 5):** All editors now use standardized `EditorSaveCallback` type: `(content: string, options?: EditorSaveOptions) => void`. SheetEditor prop renamed `saveContent` → `onSaveContent`. `sheetSaveContent` adapter in artifact-panel removed.

2. **`usehooks-ts` not in project dependencies**: Downstream tasks that need debounce utilities should use manual `useRef` + `setTimeout` pattern unless `usehooks-ts` is added to `package.json`.
