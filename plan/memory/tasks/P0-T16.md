## Deviations

### 1. Vitest `environment` not set to `jsdom`

**Plan said:** Nothing explicit about jsdom environment, but `@testing-library/jest-dom` is imported which implies DOM testing.

**Done instead:** No `environment` field set (defaults to `"node"`). Individual test files can opt-in to jsdom via `@vitest-environment jsdom` comments.

**Why:** `jsdom` is not in `package.json` dependencies. Setting `environment: "jsdom"` globally would cause Vitest to fail at runtime until jsdom is installed. The node default is safe and component test files can set their own environment.

**Trade-offs:** Slightly more ceremony per component test file; can be revisited when jsdom is added.

### 2. Playwright testDir set to `tests/e2e/` (not `tests/`)

**Plan said:** Oldapp uses `testDir: "./tests"` with `testMatch` patterns to separate e2e/routes tests.

**Done instead:** Set `testDir: "./tests/e2e"` directly, simpler without needing testMatch patterns.

**Why:** Cleaner separation between unit tests (Vitest) and E2E tests (Playwright). Prevents accidental Playwright execution of unit test files.

**Trade-offs:** E2E tests must go in `tests/e2e/` subdirectory.

## Findings

### F1: `@testing-library/jest-dom/vitest` import

Used `@testing-library/jest-dom/vitest` (not `@testing-library/jest-dom`) for the setup import. This is the correct subpath for `@testing-library/jest-dom@6.x` with Vitest — it registers matchers directly with Vitest's `expect` rather than relying on Jest globals.
