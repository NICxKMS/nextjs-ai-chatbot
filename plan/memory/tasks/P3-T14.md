## Deviations

1. **Greeting simplified**: Old app used `framer-motion` animations and accepted `availableModels` prop to display model count. New Greeting is a plain Server Component with static text — no animation dependency, no props. Rationale: spec says "Welcome text" only; keeping it as a Server Component avoids unnecessary client JS. 2. **SuggestedActions uses `setInput` + `sendMessage` instead of direct message object**: Old app called `sendMessage({ role: "user", parts: [...] })` from AI SDK's `sendMessage`. New `ChatSessionValue.sendMessage` is a `handleSubmit`-style signature `(event?) => void` that submits current `input`. So pattern is `setInput(suggestion)` → `sendMessage()`. This matches the defined ChatSessionValue contract.

3. **NoticeHandler expanded to ~25 lines (vs ~15)**: Added a `NOTICES` lookup map for extensibility (supports both `chat_not_found` and `user_not_found` from old app). Slightly over the "~15 lines" guideline but well within component size guidelines (10-50 lines for utilities).

- **BUG: `setInput(suggestion)` → `sendMessage()` race condition.**
  - `sendMessage` (defined in `use-chat-session.ts:142`) reads `input` from its `useCallback` closure: `const text = input.trim()`.
  - `input` is plain `useState("")` (line 64 of `use-chat-session.ts`). No ref-based escape hatch exists (unlike `settingsRef`, `visibilityRef`, `callbacksRef`).
  - When the click handler calls `setInput(suggestion)`, React **queues** the state update — `input` remains `""` synchronously.
  - `sendMessage()` then runs with `input = ""` → `text = ""` → `if (!text) return` (line 147) → **early return, message never sent**.
  - Result: Clicking a suggestion updates the input field text but **does not send the message**. The user would need to manually press Enter/Send.
- The deviation note acknowledges the pattern change but does not identify this race condition.
- Naming/Size: Compliant (38 lines, PascalCase, memo pattern).
