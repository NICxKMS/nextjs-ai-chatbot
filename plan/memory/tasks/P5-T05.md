## Deviations

1. **Optimistic delete pattern**: The prior scaffold awaited the server action before removing the chat from the UI. Replaced with optimistic removal (immediate UI removal + rollback on failure). This provides better UX and matches the pattern used in modern chat applications.

2. **Pending chats label**: The prior scaffold showed pending chats under a "Pending" group label. Changed to prepend them into the "Today" group section per spec: "Pending chats from usePendingChats prepended before 'Today' group". If no server Today group exists but pending chats are present, a "Today" label is shown for them.

3. **Active chat detection**: Replaced `useParams` + `usePathname` dual approach with pure `usePathname` regex extraction. Simpler, fewer imports, single source of truth.

4. **Date grouping implementation**: Replaced `Map<string, Chat[]>` with non-null assertions (`!`) with explicit arrays to satisfy Biome's `noNonNullAssertion` lint rule. Functionally identical, lint-clean.

5. **PendingChat → Chat adapter**: Added `pendingToChat()` helper function since `SidebarHistoryItem` expects the full `Chat` type but `PendingChat` lacks `userId`, `updatedAt`, and `model` fields. Provides safe defaults for fields the item never reads.

## Findings

1. **SWR page 0 overlap**: ~~The `useSidebarHistory` hook starts with SWR `size: 1` and fetches page 0 on mount, which returns the same 20 chats as `initialChats`.~~ **RESOLVED (Session 5):** `useSidebarHistory` now accepts `initialData` and passes it as `fallbackData` to `useSWRInfinite` with `revalidateOnMount: false`, eliminating the redundant page-0 fetch.

2. **Local `deletedIds` state**: Since the `useSidebarHistory` hook doesn't expose SWR's `mutate` method, optimistic deletion of server-fetched chats requires local state tracking (`deletedIds` Set). This is filtered out during rendering. On next full navigation, the server cache will be revalidated by `invalidateChatList` in the `deleteChat` action.
