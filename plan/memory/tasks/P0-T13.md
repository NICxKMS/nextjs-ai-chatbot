## Deviations

1. **Font import source**: Task spec says `geist/font/sans` and `geist/font/mono` — matched exactly. The oldapp used `next/font/google` with `Geist` and `Geist_Mono`. The new approach uses the `geist` npm package's local font exports (`GeistSans`, `GeistMono`) which bundle the fonts locally instead of fetching from Google Fonts. This is better for privacy and performance. CSS variables are `--font-geist-sans` and `--font-geist-mono` (defined by the geist package), vs the old `--font-geist` and `--font-geist-mono`.

2. **global-error.tsx uses inline styles instead of NextError**: The oldapp delegated to `NextError statusCode={0}`, which is a workaround. The new implementation renders a clear error message with a "Try Again" button directly, matching the task spec requirement for `reset()` support (which NextError doesn't expose). Inline styles used because globals.css may not be available in the global error boundary context.

3. **Added `disableTransitionOnChange` to ThemeProvider**: Not in spec but standard practice with next-themes to prevent flash-of-wrong-theme-color transitions. Minimal risk, easily removable.
